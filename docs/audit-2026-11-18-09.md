# 18 Nov — the 09:35 candle, and the mirror that never spoke

Two faults of that morning are fixed here. Both were found in the log of run **#1771**
(5m bot, 08:30–11:25 IST); both had no alarm of their own.

## Finding 1 — a candle was thrown away ten seconds after its close

```
09:40:10 no NSE bar for 2026-11-18 (last 2026-11-17) — skip
```

The 09:35 candle closed at 09:40. Ten seconds later the scan saw "no bar for today", read a
`CLOSED` market after 09:30 as **a holiday**, and stopped retrying — although its own alert
deadline was **09:43**. The bar was there by 09:45, so the candle existed and was never judged.
It is one of the three missing from `72 of 75`.

```python
# before — pipeline._run_until_ready
if (result is not None and result.get("market") == "CLOSED"
        and expected_bar.time() >= clock_time(9, 30)):
    break  # no bar at all today by 09:35 = holiday; polling cannot help
```

```python
# after — a missing bar is only a holiday after we have waited for it
if result is not None and result.get("market") == "CLOSED":
    closed_since = closed_since or now_ist()
    if (now_ist() - closed_since).total_seconds() >= NO_BAR_WAIT:   # 120s
        log.warning("no NSE bar for %s after %.0fs of polling — leaving this candle", …)
        break
```

What is unchanged: the hard deadline (`close_time + _max_lag()`, still 09:43 here), the
`waiting for completed Yahoo bar …` log line, and the live loop's own holiday rule — **three
closed candles in a row** end the session (`closed_streak >= 3`). A holiday therefore costs at
most two minutes of polling per candle before the loop exits as before; a bar one minute late
now costs nothing.

The skipped-candle line of the summary was counting **per retry**, not per candle, so it would
have said "12 candles skipped" for one candle. It is now a book of candles:

```
Candles skipped: 1 — Nifty had not published its bar when the run reached the candle
```

recorded once, at the moment `_run_until_ready` gives up on a candle (and never for a candle
that did arrive late and was judged).

## Finding 2 — every mirrored alert failed, and the summary was silent

The secondary bot (`TELEGRAM_BOT_TOKEN_2` / `TELEGRAM_CHAT_ID_2`) was refused on **every**
message of the morning:

```
ERROR nse_scanner.telegram: secondary Telegram alert was not delivered
  (check TELEGRAM_CHAT_ID_2: bot 2 must be a member of that chat); primary alert was delivered
```

That is a **configuration** fault, not a code fault: the chat id names a chat bot 2 is not in.
The primary alerts were delivered, the run stayed green, and the only trace was one log line
per alert — the day's summary said nothing, so a reader of the summary could not know that half
of the alerting pair had been dead all morning.

`telegram.send` now keeps a count (`telegram.secondary_failures()`, also incremented for a
half-configured pair) and the 5m summary names it once:

```
⚠ mirror alerts not delivered: 12 — TELEGRAM_CHAT_ID_2 names a chat that bot 2 is not a
  member of (bot 1's own alerts were delivered)
```

The line appears only when there is something to say. Delivering the alert is still the
primary bot's job, and a refused mirror still does not make the pipeline resend.

**Only the repository owner can fix this**, in *Settings → Secrets and variables → Actions*:
either put bot 2 in the chat named by `TELEGRAM_CHAT_ID_2`, or point `TELEGRAM_CHAT_ID_2` at a
chat bot 2 is already in, or delete both `_2` secrets to run with bot 1 alone.
