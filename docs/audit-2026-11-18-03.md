## 2. Why the pick is stamped 09:45 and not earlier

The pick is not one test on CDUR. Five conditions must hold on the same closed candle
(`market.py`):

| # | gate | rule | when it can first be true |
|---|---|---|---|
| 1 | direction committed | `dir_state ≠ 0`: close<VWAP and EMA9<EMA21<EMA50 and `mtf_bear ≥ 2` and `adx ≥ 20`, **or** the early variant that needs `or_dn` | the OR variant needs the opening range, which closes at **09:45** (`OR_MINUTES = 30`) |
| 2 | regime ≠ CHOP | `CHOP = commit_side == 0 and adx < 20` | at 09:20 with nothing committed the picker returns `WAIT` before it reads a sector |
| 3 | confidence ≥ 55 | `PICK_MIN_CONF = 55`; `BUILDING` = 55–69 | your 09:45 block prints **68 BUILDING** — the first tier that allows a pick |
| 4 | sector persist ≥ 50 | `PICK_MIN_PERSIST = 50`, flat (`PICK_CONF_SCALED_FLOOR=0`) | CDUR was **93** at 09:45; `persist_bear` is EMA-5 smoothed, so it ramps rather than steps |
| 5 | sector index fresh | index lag `> SECTOR_MAX_LAG_BARS = 2` removes the sector from PERSIST − | feed-dependent |

Gate 3 is the one that moves with the clock: `_dir_conf` = MTF spread 35 + **consecutive
closes below VWAP** 25 (capped at 6 candles) + ADX 25 + |npos−50|·0.3, **+5** for an OR break
/ **−2** without one. Two of those legs are candle *counts*, and one literally cannot exist
before 09:45. That is why 68 lands there and then climbs 83 → 86 → 96 as the same trend ages.

## 5. Three discrepancies worth recording

**5.1 Two blocks stamped 09:45 disagree on the bear book.** The 5m block read
`MET 78 · AUTO 66/67`; bot 3's 09:45 block read `MET 85 · DEF 65` (and `PERSIST + PHA 34`).
CDUR 93 and conf 68 match, so this is not a different candle — it is the **projection**:
bot 3's market at 09:46–09:49 is built from the *forming* 09:45–09:50 candle
(`projected_market`), bot 1's from the closed one. A block's timestamp is the candle's
**open**, not the moment of computation. Consequence: cross-bot comparison is only valid on
close blocks. *Unverified* which of the two was the projected read — needs the log.

**5.2 One pick window, two different confidences.** The ×6 digest says
`Market BEAR (81%)`; the KALYANKJIL straggler for the *same* window says `Market BEAR (67%)`.
`_catch_up` quotes the pick it ran with, and bot 3 re-derives the pick on every minute, so a
name caught on a later tick can carry a number 14 points away from the message above it.
The label added in `#40` (`2 more from the same pick`) makes the pair readable; the number
itself stays tick-dependent by design. Not a bug, but do not read the conf off a catch-up as
"the" conf for that candle.

**5.3 Breadth improved while the bear score rose.** Breadth went `1▲/14▼` (09:45) →
`3▲/12▼` (10:20) → `4▲/11▼` (10:25 and 10:35) while `conf` climbed 68 → 96 and CDUR stayed
98–99. `_dir_conf` has no breadth leg (it is MTF + consecutive-VWAP + ADX + range position),
so this is expected — but it is worth knowing that "TREND-LOCK 96%" does not mean breadth is
deteriorating, and a user watching breadth could reasonably read the label as contradicted.

Also recorded, fixed earlier: both catch-up messages ended *"bot 1 has none for these either"*
at 09:46–09:49 — **before bot 1 had run that candle at all** (its 09:45 block closes at
09:50). The claim was premature even when it turned out to be true; `#39` replaced it.
